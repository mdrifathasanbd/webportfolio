Easeora Content Access

Custom WordPress plugin built for secure content restriction.

A focused plugin-development project that replaced an outdated restriction plugin with a lightweight, secure, and centrally managed solution designed for WordPress, Elementor compatibility, and WordPress.org publication.

WordPress Plugin Development Security Performance Optimisation WordPress.org Publishing
MY ROLE WordPress Plugin Developer & Publisher

I handled the complete plugin lifecycle, including planning, architecture, PHP development, access-control logic, admin management tools, security testing, performance optimisation, WordPress.org compliance, documentation, branding preparation, and SVN publishing.

PROJECT OVERVIEW

Replacing an outdated restriction plugin with a cleaner, safer WordPress solution.

I developed Easeora Content Access, a lightweight WordPress plugin that allows website administrators to restrict selected pages and posts so they can only be viewed by logged-in users.

The project began as a replacement for an outdated content-restriction plugin that was repeatedly being flagged during website security scans.

The client wanted to preserve the simplicity of the existing workflow while improving security, performance, content protection, administration, compatibility, and long-term maintainability.

The project expanded from replacing a simple restriction feature into a complete WordPress plugin that could be centrally managed and published through the official WordPress.org Plugin Directory.

THE CHALLENGE

The replacement had to stay simple without compromising protection.

  • Preserve the existing one-click restriction workflow
  • Remain lightweight and avoid unnecessary performance impact
  • Work with Elementor and standard WordPress editors
  • Restrict both pages and posts
  • Prevent restricted content from appearing publicly
  • Protect restricted content from search engines
  • Protect restricted content from feeds, APIs, and sitemaps
  • Allow administrators to manage restrictions centrally
  • Support migration from the previous plugin
  • Follow WordPress.org development and security requirements
THE SOLUTION

A focused access-control plugin built with native WordPress functionality.

I developed Easeora Content Access using native WordPress functionality with a focus on keeping the plugin simple, secure, and lightweight.

Administrators can restrict individual pages or posts directly from the WordPress editor using a simple restriction option. For larger websites, restricted content can also be managed from a dedicated dashboard so administrators do not need to open every page individually.

CORE FEATURES

Built to solve the access-control problem without turning into a heavy membership system.

  • One-Click Page & Post Restriction: Administrators can quickly mark selected WordPress pages and posts as restricted.
  • Bulk Restricted Content Management: A central management interface allows administrators to review and manage restricted and unrestricted content from one place.
  • Custom Login Message: Logged-out visitors see a custom message such as “You are required to login to view this page.”
  • Login Redirection: Users can authenticate and then return to the restricted page they originally attempted to access.
  • Search Engine & Sitemap Protection: Restricted content is protected from being exposed through public search-related areas.
  • REST API Protection: The plugin prevents restricted content from being unintentionally exposed through applicable WordPress API requests.
  • Feed & Archive Protection: Restricted content is prevented from appearing publicly through feeds and archive-related areas where protection is required.
  • Lightweight Architecture: The plugin was intentionally built as a focused access-control solution without unnecessary features or heavy dependencies.
  • WordPress Dashboard Integration: Administrators can manage menu location, login message title, login message, and restriction management directly from the dashboard.
SECURITY & PERFORMANCE

Developed as a focused replacement, not an oversized workaround.

Security was an important reason for developing the replacement plugin. The plugin was developed and tested with a focus on safe WordPress coding practices, proper handling of restricted content, preventing public exposure, WordPress.org coding and security requirements, avoiding unnecessary third-party dependencies, and maintaining a focused attack surface.

The plugin was also designed to remain lightweight and avoid unnecessary performance overhead. The goal was to provide access-control functionality without introducing a large membership system or loading features the client did not need.
